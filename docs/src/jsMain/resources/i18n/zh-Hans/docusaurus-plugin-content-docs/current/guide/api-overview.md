# API 概览

声明与 `editor.api.d.ts` 一一对应：名字一致、成员一致，一个上游命名空间对应一个 Kotlin 包。
本页说明需要额外规则的几种形态——也就是 Kotlin 无法直接照抄 TypeScript 的地方——以及各类声明去哪找。

## 包结构

| Kotlin 包 | 上游 | 文件 |
| --- | --- | --- |
| `io.github.shijianjs.ktjs.monaco` | 模块自身的导出与 `Monaco` 入口 | `Monaco.kt`、`MonacoModule.kt`、`root/*` |
| `…monaco.editor` | `namespace editor` | `Editor*.kt` |
| `…monaco.languages` | `namespace languages` | `Languages*.kt` |
| `…monaco.worker` | `namespace worker`（只有类型） | `WorkerTypes.kt` |

命名空间包里按声明种类拆文件：`…Types`（interface）、`…Classes`、`…Enums`、`…Unions`、
`…Literals`（字符串字面量联合）、`…Namespace`（命名空间自身的函数与常量）。看文件名就知道自己读的是
哪类声明。

`worker` 在运行时没有对应的值：上游在这个命名空间只声明类型，导出列表里也没有它，所以 `Monaco`
不提供 `worker` 访问器，`WorkerTypes.kt` 里放的是编写 worker 上下文时需要的类型。

## `Monaco` 入口

`Monaco` 是唯一手写的对象，其余都是生成的。

```kotlin
Monaco.editor      // EditorNamespace：create、setTheme、setModelMarkers、tokenize……
Monaco.languages   // LanguagesNamespace：register、registerCompletionItemProvider……
Monaco.environment // 全局 MonacoEnvironment 钩子（getWorkerUrl / getWorker / globalAPI）
```

`Monaco.editor`、`Monaco.languages` 和五个值类都是模块命名导出的访问器
（`@JsModule("monaco-editor")` + `@JsName("editor")`），因此拿到的是包自己的对象，不是副本。

## 值类

`Uri`、`Position`、`Range`、`Selection`、`KeyMod` 是以**值**导出的：既有静态成员
（`Uri.parse`、`Range.fromPositions`、`KeyMod.CtrlCmd`），也有构造函数。Kotlin 的 `@JsModule`
作用在 class 上会导入模块的**默认导出**，而这个包没有默认导出，于是这些类被声明成两个接口：

- `Uri` —— 实例类型（一个已存在的 URI 的成员）；
- `UriStatics` —— 静态成员，在 `root/RootModule.kt` 里按名字绑定到模块导出，通过 `Monaco.Uri` 访问。

构造必须真正调用构造函数，`Monaco` 提供四个工厂：

```kotlin
val uri = Monaco.uri("file:///src/main.kt?x=1#frag")   // Monaco.Uri.parse
val position = Monaco.position(1.0, 1.0)               // new Position(1, 1)
val range = Monaco.range(1.0, 1.0, 3.0, 5.0)           // new Range(1, 1, 3, 5)
val selection = Monaco.selection(1.0, 1.0, 3.0, 5.0)   // new Selection(1, 1, 3, 5)
```

它们通过 `Reflect.construct` 造实例：`external class` 想用 `new` 就必须导入自己的模块，而上面这些
都做不到。`KeyMod` 上游没有实例成员，因此只声明了静态成员。

## 字面量联合

`theme`、`severity`、渲染类型、`SelectionDirection` 等在上游是字符串（或数字）字面量。每一种都变成
`sealed external interface` + 包装 `String`/`Double` 的同名工厂 + 常量对象：

```kotlin
theme = BuiltinThemes.vs              // "vs"
theme = BuiltinThemes.vsDark          // "vs-dark"；驼峰命名，所以不用反引号
severity = MarkerSeveritys.Error      // 8
direction = SelectionDirections.LTR   // 0
```

常量在运行时就是上游那种值——`String` 或 `Double`——而类型仍是受检查的。Kotlin 标识符放不下的
连字符之类只影响常量名，它携带的字符串原样保留。上游没枚举到的取值用同名工厂
（`BuiltinTheme("solarized-dark")`）：monaco 接受任何通过 `defineTheme` 注册过的主题名。

## 类型联合

像 `string | IMarkdownString`、`Promise<Worker> | Worker` 这样的联合，变成一个不透明
`external interface`，每个分支一个同名工厂：

```kotlin
// IMarkdownStringOrString、StringOrDouble、PromiseWorkerOrWorker 等
val message = IMarkdownStringOrString("plain text")
val contents = IMarkdownStringOrString(unsafeJso<IMarkdownString> { value = "**bold**" })
```

如果联合里有 `any`/`unknown`，整个联合收敛为 `JsAny`——那种情况下本来也没有可收窄的信息。

## 可选成员与方法

- 可选属性是 `var x: T?`；「没设置」就是 `undefined`，读回来是 `null`。
- 可选**方法**（`getWorkerUrl?(id: string, label: string): string`）变成可空的函数属性
  `var getWorkerUrl: ((String, String) -> String)?`。这样字面量才能只提供其中一个：

    ```kotlin
    Monaco.environment = unsafeJso<Environment> {
        getWorkerUrl = { _, _ -> "editor.worker.js" }
    }
    ```

- 必选方法仍是 `fun`，参数写错就是编译错误。

## 命名空间即接口

`monaco.editor` 在运行时是一个对象，成员是函数和常量。这里声明为
`external interface EditorNamespace`，通过 `Monaco.editor` 访问，所以调用写起来和上游一样：
`Monaco.editor.getModels()`、`Monaco.languages.getLanguages()`。

## 对象与回调

- 对象字面量用 `js.objects.unsafeJso<T> { … }`：每个属性都会对照 `T` 检查。不要用 `js("{…}")`。
- 回调是 Kotlin 函数类型（`(String) -> Unit`），Promise 是 `kotlin.js.Promise`，数组是 `Array<T>`，
  集合是 `js.collections.JsSet`，字典是 `js.objects.Record`。
- DOM 参数用 `kotlin-browser` 的 `web.html.*` / `web.dom.*`，不用 `org.w3c.dom.*`。

## 重新生成

```bash
python scripts/generate-api.py            # 写出声明
python scripts/generate-api.py --report    # 打印统计与被跳过的项
```

脚本是生成文件的唯一来源，所有生成文件都带 `// Generated by scripts/generate-api.py` 头。
上面这些形态背后的决策记录在[开发文档](https://github.com/shijianjs/ktjs-monaco-editor/tree/main/docs/development)，
`docs/development/coverage.md` 则逐条列出每个声明的状态，以及被排除的声明和理由。
